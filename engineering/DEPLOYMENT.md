# Deployment culture / P0.F

CI is read-only; no secrets or write token for PR code. A trusted controller on main handles incidents, safe fixes and eligible merges. It never runs PR code. Owner-only same-repo PRs; changes to workflow/security policy are deliberately excluded from auto-merge. Branch protection / required checks must be configured at repository level; the connector cannot edit those settings.

State: QUEUED → CI → READY → MERGED → DEPLOYING → VERIFIED. FAILED (test), BLOCKED (conflict/security), DEFERRED (stale) are separate. A green CI run for old SHA never qualifies. Controller uses event-driven workflow_run and periodic reconciliation, not constant polling. Before merging next eligible PR, confirm public release marker equals current main. Merge API supplies expected head SHA. Bot merge explicitly dispatches deployment because GITHUB_TOKEN push events do not start workflows. Native CI/CD concurrency is NOT a durable FIFO queue; controller serializes merges, skips stale release and checks marker before the next merge. Direct owner pushes are outside that guarantee.

Safe retry cap: 3 total attempts on known transient runner/network errors. Known sidebar migration fixer can patch a precisely matched config once; re-run CI on new SHA. Unknown CI failures and semantic conflicts: incident, research, minimal patch and regression by agent. Nonconflicting branch updates use GitHub update-branch with expected head where possible; no blanket conflict resolution.

Bootstrap requirements: set Pages source = GitHub Actions; protect main with CI job required; enable actions permissions as needed. Add generated package-lock.json using npm install and switch to npm ci. Pin action SHAs after validation. No automatic arbitrary AI research: a connected code agent/model is required for novel bugs and source verification. The controller creates evidence-based triage issues and known-fix links; a human/agent must verify the diagnosis before marking resolved.

Tech Blog batch process: trusted closed engineering incidents with verified SHA, earliest first, five per group, idempotent candidate issue. Editorial candidate includes issue links; after review write static JSON post in src/data/techblog via PR. No public raw diagnostic logs. Automated publication requires an authenticated agent with scoped write access and content review. Quora visual reference could not be verified directly (robots); first design is editorial-inspired pending visual parity.
