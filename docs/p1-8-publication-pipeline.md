# P1.8 — Publication Pipeline

The private Back Office `/admin/pipeline/` uses the existing trusted FIFO Issue parser, six milestone progress renderer and public read-only GitHub client. No new publishing engine, no direct mutation, no server PAT and no anonymous dashboard. The queue is sorted by Issue number. Detail evidence is fetched only for the oldest unverified Issue to bound API use. Each card exposes available exact submission, HEAD, base, merge and verified release SHA, with Issue/PR/Actions/public article links. Current PR HEAD/base must agree with the FIFO marker before reporting CI success; unrelated events and SHA do not count. Exact merge deploy success is distinct from verified production; even a successful verify job alone is not a closed trusted receipt. For descendant deployments remain conservative until the trusted FIFO marker verifies ancestry and URL. Sheet sync is separate from production verification. Initial/manual refresh preserves last snapshot as stale on error; no polling. Local receipts include only already-public title, digest and submission SHA (not private content or credentials), shared by Editor V2 and Sheets, limited to 50 and removed when accepted. Pending pre-Issue receipts are device-local and not globally complete. P1.6 scheduled receipt integration and full cross-stage regression remain P1.9.

Draft PR pending earlier P1 dependencies and integration; no actual content submitted. Existing FIFO and trusted writeback untouched. Tests use synthetic public-shaped GitHub records with wrong HEAD rejection, deploy-not-verified, verified marker, stale network and responsive layout.
