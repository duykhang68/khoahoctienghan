# Editor V2 — independent online Editorial Studio

URL after production verification: /khoahoctienghan/techblog/editorv2/. Standalone Astro/browser block editor using shared editorial design tokens. No V1 imports or changes, localhost, Codespaces, additional hosting or dependencies. Supports new articles, per-block formatting, notes, tables, WebP (max dimension 1600), reordering, approximate preview, browser-local draft and backup. Existing article edits, scheduled time publishing, cross-device drafts, selection-level formatting and full Visual Editorial 2.0 diagrams are not implemented.

## Online authentication
The public page is visible to anyone; only the repository owner's fine-grained PAT, scoped to this repository with Contents read/write, can submit. Token is held in memory only, never in drafts, exports or URLs. Browser-only authentication is not a server-side secure session: scripts on this origin or extensions represent a risk. Use short expiration and revoke when not needed. Never share credentials in chat or source.

## FIFO publication
Explicit confirmation creates an immutable submission commit on content/editor-v2-<payload SHA256>, containing only editor-submissions/<payload SHA256>.json. This is public repository data, not a private draft. No writes to main, no direct PR from the browser. Stable digest deduplicates identical submissions. The trusted-main queue workflow reacts to the owner's push or explicit repository_dispatch after the ref is created (same digest/commit deduplication), validates the ref and payload, and creates one bot-authored tracking Issue; issue number is the acceptance order. Concurrent push events can arrive out of order, so FIFO is defined by the assigned Issue number, not browser clock. One worker handles the oldest non-VERIFIED issue, regenerating against current main if an unrelated change makes an untouched queue-owned PR stale. A fresh content-only PR is created with the existing repository-scoped Engineering GitHub App; native PR CI and exact HEAD checks remain mandatory, normal squash merge rules apply. If the App is missing, or validation/CI/merge/deploy fails, queue stops at the head. Closing an unverified Issue is not permission to skip it. No executing submission branch code. Only after successful release verify, first-parent ancestry of the published marker and a successful public article route does the worker close the Issue as VERIFIED. Later submissions cannot advance before that. Workflow-run events resume reconciliation; a 20-minute fallback and manual dispatch cover missed wakeups. GitHub Actions scheduling is best-effort. No real token or test article is published by CI.

Both destinations use the same canonical Astro body and metadata contracts, validate WebP bytes/hashes and preserve titles, labels, Series and GMT+7 timestamps. No handwritten Markdown required. All existing URLs remain unchanged.

## Dual workspace
The same online route contains Tech Blog Editor and Knowledge Base Editor with fixed destinations, independent browser-local draft keys, distinct block ordering and optional outlines, and preview aligned with the public site’s compact pastel cover and metadata rail. Tech Blog categories remain inferred after publishing; Knowledge Base explicitly selects the actual topic. Existing single-draft data is copied to its original destination and retained as a recovery copy. Switching saves the outgoing draft and resets submission confirmation; GitHub authentication stays in page memory. Both editors share the existing FIFO queue. Preview is approximate; editing already-published articles is still not implemented.

## Series planner
Both workspaces display the selected-episode projection (part / total), remaining episodes and percentage after that episode, and a calendar-day deadline based on Asia/Ho_Chi_Minh. Due today and overdue are explicit, incomplete or invalid inputs do not display invented percentages. Projection is not evidence of publication; no schema, FIFO or production content changes.

## Long editorial blueprints
Six full original templates from reddit-editor commit 1a1c3f3efc72b530c1c76ce494bdebd8baa3f795 (`apps/web/src/components/seriesBlueprints.js`) are copied verbatim as static data, not imported at runtime from V1. The separate collapsible selector works in both sub-editors without enabling Series; selection previews the complete heading structure and an explicit button appends editable blocks. Original H2/H3/H4 hierarchy is preserved; writing prompts (including review caveats and spoiler warning guidance) are visible non-published guidance, not fabricated article content. Enter actual text into a block for it to appear in preview and published data. Remove unused optional headings/sections before sending. The existing four-heading quick outline and FIFO submission flow remain unchanged.

## Draw.io Diagram Studio
Both workspaces include a draw.io block. Create/edit in an on-demand sandboxed iframe at `https://embed.diagrams.net` using documented JSON embed protocol. Only diagram XML, not GitHub credentials or other draft fields, is passed to the frame; source/origin and export correlation are checked. Import/download `.drawio` XML (300 KB max); save renders the selected page to a maximum 1600px WebP (1.5 MB max) with required alt and optional caption. The browser draft retains XML and WebP. FIFO creates a content-addressed source file in `diagrams/editor-v2/<image SHA256>-<XML SHA256>.drawio` outside public/ plus the normal WebP in public/media/studio; images alone appear in blog pages. Source files in the public repository are public. For later use open the repo in github.dev, install the unofficial draw.io extension from Henning Dieterichs and open/download the source. Reimport edited XML into Editor V2 and save to produce an updated WebP; editing XML directly in GitHub does not regenerate the published image. Existing published articles are still not editable in V2. Do not commit diagram changes directly to main. No Codespaces, V1 changes or release workflow changes. Embed requires network and the external draw.io service; CI uses a protocol fixture, not a live external service.

References: https://www.drawio.com/docs/integrations/github/edit-diagrams-with-github-dev/ and https://www.drawio.com/docs/reference/embed-mode/.

## P1.2 — Inline visual formatting

Private Back Office Editor V2 supports selecting text within paragraph, quote, note and list blocks, then applying bold, italic, underline or strike; the actual text formatting is visible in the editing surface and preview. Keyboard Ctrl/Cmd+B/I/U supported. Paste imports plain text only, no executable HTML. Canonical text/mark runs preserve old block-level marks and are validated before FIFO serialization; backup/import keeps runs. Shared Astro body contract and publication flow are unchanged. Titles and code remain plain fields, tables use existing visual cells, diagrams use existing draw.io integration. Native editing undo across custom toolbar changes is not guaranteed. The preview follows the same marks, not pixel-identical public rendering. Existing article editing remains P1.3.

## P1.3 — Private Content Library

Private /admin/library/ loads published SHA and all Tech Blog/Knowledge Base records (no index pages). Search/filter, open public article, modify title/summary and existing text nodes for Studio documents or legacy Tech Blog paragraphs. Unknown MDX body remains unchanged; no lossy conversion or raw Markdown editing. Unlisted lesson titles are labeled by slug until the index is updated. Edit/delete requires existing owner repo-scoped PAT in memory, explicit consent, exact published SHA == main, read-only source fetch, and a draft review PR. Delete additionally requires exact slug and removes the article/index entry and corresponding Studio data where applicable; media and unrelated content are not deleted. No merge or production writes from Library; reviewer must check native CI and diff. This reuses current PAT-based submission authorization; server-side GitHub App credential migration stays separate. Review draft PRs manually; a changed main requires reload rather than overwrite. No automatic live publishing during tests.

## P1.5 — Shared local media management

Both visual workspaces use the same local encoder and media validation as draw.io and the FIFO model. Upload a single image or up to ten at a time via the draft media panel. Source formats PNG/JPEG/WebP/GIF (single frame), max 30 MB and 25 MP decoded; WebP result preserves aspect ratio, does not upscale, max edge 1600 px, max 1,500,000 bytes. The draft panel shows dimensions, bytes and missing alt per image; publication requires nonempty alt. Duplicate image bytes use the existing content-addressed asset path. Nothing is uploaded externally until explicit publishing; private drafts remain in the browser. No R2/storage provisioning, published asset deletion, new payment or global CMS library; P1.6 handles private persistence separately.

## P1.3 follow-up — Open existing article in Visual Editor V2

Content Library cards link to the signed-session Editor route with a fixed category/slug. The editor reads the current published SHA and source, opens an isolated revision (not a new article or FIFO submission), and creates a draft review PR only after owner PAT verification, explicit consent and exact main SHA checks. Existing title, summary and supported canonical blocks are editable; slug/date/other metadata stay unchanged. Legacy Tech Blog sections use fixed structure with text edits only, retaining existing illustration fields; preview does not reproduce independent legacy visuals. Canonical import requires lossless round-trip; existing images or unsupported nodes and arbitrary legacy Markdown/MDX fail closed with a link to the existing limited management form. No private draft persistence, no automatic publishing, no production UAT yet.
