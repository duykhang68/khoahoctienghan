# P1.6 — Private Drafts & Scheduling (device-local first)

Private `/admin/drafts/` stores up to 50 explicit immutable copies of Editor V2 drafts in same-origin IndexedDB and restores with confirmation and a backup of the current named draft. Separate workspace drafts remain local. There is no server-side draft database, cross-device sync, encryption at rest by this app or secret/token persistence. Anyone with access to the same browser profile/devtools can inspect local storage; do not use shared devices. A logout revokes the cookie, not the local draft store.

Schedule an immutable copy only after explicit public-submission consent, strict Vietnam time (GMT+7 seconds; omitted zero seconds normalized), content validation, and future timestamp. This is a submission schedule, not guaranteed publication time. A visible open tab checks every 30 seconds, and requires a valid Back Office session and an in-memory owner GitHub PAT; an expired session prevents sending. Web Locks serializes across tabs; unsupported browsers cannot auto-send. Only the oldest due row is attempted. Reuse the existing FIFO publisher's immutable content digest, never bypass issue order or write main. A failed or interrupted send blocks subsequent due rows; explicit retry uses the same snapshot, not current editor contents. Cancellation only before first send. Receipt means submitted, not production.

No new Cloudflare storage, GitHub App credentials, cron, or billing changes are included. Reliable unattended scheduling while the tab is closed, private server persistence and server-scoped GitHub App authentication are not implemented and must remain open acceptance criteria until authorized infrastructure exists. Tests use fixtures, never publish a real article. Merge after P1.3–P1.5 dependency integration, regression and required review.
